# 2026-11-08: bug 9, review of the analysis and of draft PR #67

A read-only review of the Bug 9 document ("HDR screenshots too bright or too dark") and of `tools/hdrcapture` on `master` (PR #65) and in draft PR #67 (`f1ceb61`), against the Windows capture APIs and the owner's two HDR reports. No code was changed; the full review with a ranked suggestion table is in the project (Claude Doc "Review of the Bug 9 analysis and fix (PR #67)").

- **Analysis:** holds. The scRGB model (1.0 = 80 nits, SDR white = `SDRWhiteLevel` / 1000) is right, the owner's colours recompute to the document's numbers, the 3.0.1 window darkness (white 170) is exactly a 2.0 frame divided by 5.0, and the 3.0.1 area miss is `QScreen::name()` being the model name in Qt 6. The SDR-window scale of 2.0 from Windows.Graphics.Capture is measured, not explained; the calibration makes the explanation unnecessary.
- **Solution:** sound. The composed desktop is the only surface on the screen's scale, so calibrating each window frame against it is the principled fix given that Windows reports no per-window scale. The border request and the fallbacks are correct.
- **Before release (suggestion 1):** `duplicateFrame` uses a frame only when `LastPresentTime != 0`. The duplicated texture is the whole desktop on every successful `AcquireNextFrame`, so on a static desktop the five 500 ms attempts can wait 2.5 s and then fall back to GDI, which is the bug itself. Use the texture on any successful acquire and shorten the timeout.
- **With PR #67:** two more `matchScale` tests (ratio 1.0 for Chrome's HDR state; a dark window calibrated from its text), and a QA step that puts Chrome into its HDR state on demand (HDR video, or `--force-color-profile=scrgb-linear`, unverified) rather than waiting for it.
- **Later:** crop the desktop frame instead of scaling the WGC frame when the window is uncovered (exact, and no Windows 10 border flash); share one D3D11 device and copy only the window's rectangle if the report shows a capture over about 200 ms; let the borderless request retry; accept or log the scRGB colour space.
- **Release:** the `v3.0.1` tag is already public; releasing the fix as 3.0.2 is cleaner than moving the tag (owner's call). The release checklist should require the Windows QA pass before tagging, since PR #65's defect could only show on an HDR machine.
