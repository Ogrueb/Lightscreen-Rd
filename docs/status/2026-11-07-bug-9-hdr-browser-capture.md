# 2026-11-07: bug 9, browsers captured too bright on an HDR monitor

- **Report:** the owner hit bug 9 on 3.0.0 with a Chrome tab (a GitHub page, area capture). The capture is washed out with coloured fringes.
- **Measured from the owner's file:** GitHub's colours come out about 5 times too bright in linear light, clipped per channel. The green button `#1f883d` is `(72, 255, 134)`, body text `#1f2328` is `(75, 82, 93)`. Scaling the true colours by 5 in linear light and clipping gives `(74, 255, 133)` and `(74, 82, 92)`. That is what reading an scRGB desktop with 1.0 as white gives when SDR white sits at 5.0 (400 nits): Qt's GDI grab gets Chrome's hardware-composited content without the SDR white level. The cause is inferred from the numbers, not reproduced.
- **Fix:** new `tools/hdrcapture` (Windows code, the conversion is portable). For each screen, `Screenshot::grabDesktop` first calls `HdrCapture::grabScreen(screen->name())`. If that DXGI output is in HDR (`DXGI_COLOR_SPACE_RGB_FULL_G2084_NONE_P2020`), it duplicates the output in FP16 (`IDXGIOutput5::DuplicateOutput1`), divides by the monitor's SDR white level (`DISPLAYCONFIG_SDR_WHITE_LEVEL`) and encodes sRGB. HDR highlights above SDR white clip. On SDR monitors, on Linux, or on any failure (e.g. a hybrid-GPU laptop where duplication is unsupported) it returns a null pixmap and Qt's grab runs as before. Full screen, current monitor and area capture all go through `grabDesktop`. Window capture (`os::grabWindow`, PrintWindow) is unchanged.
- **Tests:** new suite `tst_hdrcapture` (15 suites): SDR white maps to white, the owner's colours round-trip at white 5.0 and reproduce the bug's values at 1.0, clipping, row pitch, invalid input, fallback. Linux build and `xvfb-run ctest` pass locally; the Windows code is compiled only by CI.
- **Windows check:** `docs/windows-qa/2026-11-07-hdr-browser-capture.md`, which also asks whether window capture is affected.
- **Not checked:** the AMD driver's lowered SDR baseline (bug 9's entry). If the screen is dimmer than Windows' SDR white level says, the capture will still be brighter than the screen, though no longer clipped.
